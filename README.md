# 筋トレログ

持っている機材と使える時間に合わせて筋トレメニューを提案し、記録・振り返り・目標調整までを行うアプリ。
スマホ・PC 兼用の PWA（ブラウザで動き、ホーム画面に追加するとアプリのように使える）。

データは端末のブラウザ内（IndexedDB）にのみ保存され、サーバーには一切送信されない。

## 動かす

```bash
cd kintore-app
npm run dev
```

`http://localhost:5173/` を開く。
同じ Wi-Fi につながっているスマホからは、起動時に表示される `Network: http://192.168.x.x:5173/` を開く。

本番ビルドと確認:

```bash
npm run build
npm run preview
```

`dist/` を任意の静的ホスティング（Netlify / Vercel / GitHub Pages など）に置けばそのまま動く。
HTTPS 経由で開くと「ホーム画面に追加」でスタンドアロン起動＆オフライン利用ができる。

> 開発中に CSS やコードの変更が反映されないときは、ファイル監視の取りこぼしが原因のことがある。
> 対象ファイルをもう一度保存し直すか、`npm run dev` を再起動する。

## ホーム画面のアイコン

スマホは「ホーム画面に追加」で普通のアプリのように起動できる。そのときのアイコンは `public/` の PNG が使われる。

iOS はホーム画面アイコンに **PNG しか読まない**（SVG を指定するとページのスクリーンショットが出てしまう）ため、
実体の PNG を用意している。形を変えたいときは生成スクリプトの座標を編集して再生成する。

```bash
node scripts/generate-icons.mjs
```

`scripts/generate-icons.mjs` の `drawIcon()` が図形の定義。512×512 を基準に座標を書くと、
`pwa-192.png` / `pwa-512.png` / `apple-touch-icon.png` (180) / `favicon-32.png` が出力される。
外部ライブラリは使わず、4倍で描いて縮小することで輪郭を滑らかにしている。
`public/app-icon.svg` は同じ形を手で書いたものなので、変更したら合わせて直す。

Android はアイコンを円などに切り抜くので、絵柄は中央60%の範囲に収めてある。

## できること

### 1. プロフィール（設定タブ）
身長・体重・性別・年齢・活動量・トレーニング歴・1日に使える時間・週の日数・持っている機材（ダンベル5kgなど所有重量まで）。
BMI・標準体重・維持カロリーがその場で出る。

### 2. 部位と目標（目標タブ）
人体図（前面・背面）をタップして鍛えたい部位を選ぶ。目標タイプは筋肥大／筋力／減量／持久力の4種。
目標体重と期限を入れると、安全なペース・1日の目安カロリー・タンパク質量・4段階のステップが出る。

### 3. メニュー提案と記録（メニュータブ）
選んだ部位・目標・所有機材・使える時間から種目を自動で組む。

- 所有しているダンベルの重量に丸めた推奨重量つき
- 2回目以降は前回の実績を表示し、そこから次回の重量を決める（漸進性過負荷）
- セットを完了すると休憩タイマーが自動で走る（音・バイブつき、+30秒／スキップ可）
- 推定1RMが過去最高を超えると自己ベスト更新を表示
- 減量／持久力の目標では有酸素運動（時間と目標心拍ゾーン）も提案

### 4. アチーブメント（記録タブ → 実績）
連続記録日数、週の目標に対する進捗、直近4週間のカレンダー、毎日リセットされる4つのミッション、14種類のバッジ。
新しいバッジを獲得するとホームで通知される。

### 5. 統計と目標の見直し（記録タブ → 統計）
月次・年次の集計、体重の推移（目標体重の基準線つき）、月別の総挙上量とトレーニング回数、部位別のセット数バランス。
そこから **目標の調整を提案** する。

- 実測の体重ペースと、目標日までに必要なペースを比較
- 遅すぎる／速すぎる／逆方向を判定し、実測ペースでの到達予定日を計算
- 週の目標日数と実績の乖離を検出
- 直近8週間で鍛えていない大きな筋肉を指摘
- 提案はワンタップで適用できる（目標日の変更・週の目標日数の変更）

### 6. トレーニングの自動評価
完了すると、その日の内容を自動で100点満点＋S〜Dで採点します。

- 完了率 (30点) / 前回比のボリューム (25点) / 前回からの進歩 (25点) / 有酸素または時間の使い方 (20点)
- 推定1RM (Epley式) が過去最高を超えた種目は自己ベストとして表示
- 「この重量で全セット12回に届いているので次回は1段階上げる」といった具体的な助言つき
- 記録タブの各日からも後で見返せる

### 7. 種目の自己編集（設定 → 種目の管理）
- 自分の種目を追加・編集・削除できる（部位・機材・動作の種類・初回の推奨重量まで指定）
- 組み込み種目を「使わない」にするとメニューに出てこなくなる
- 組み込み種目をコピーして自分用に書き換えられる
- 記録中のメニューにも、その場で種目を足したり外したりできる

### 8. 記録の編集（記録タブ → 履歴）
過去の記録の重量・回数・完了状態・有酸素・体重・メモを後から直せる。種目単位の削除も可能。

### 9. リマインダー（設定）
曜日と時刻を決めて「そろそろトレーニング」を知らせます。実際に効く順に3段構えです。

1. **カレンダー登録 (.ics)** — 端末のカレンダーに繰り返し予定＋アラームを入れる。最も確実
2. **通知の予約** — 対応ブラウザ (Notification Triggers) ならアプリを閉じていても指定時刻に届く
3. **開いている間のタイマー＋次回起動時の未実施表示** — どの環境でも動く保険

ブラウザだけで完結するアプリなので、サーバーからのプッシュ通知は使えません。
その制約と、いまの端末で何が使えるかは設定画面に明示しています。
iPhone / iPad ではホーム画面に追加して起動した場合のみ通知が使えます。

### 10. その他
- 体重はトレーニングしない日もホームから1タップで記録できる
- 記録画面から JSON で書き出し／読み込み（機種変更や別端末への移行用）

## 設計メモ

### メニュー生成（`src/lib/planner.ts`）

1. 所有機材とトレーニング歴で実施可能な種目に絞る
2. 1種目ずつ貪欲に選ぶ。スコアは「主動筋が対象部位なら3点・協働筋なら1点」を基本に、
   - すでに他の種目でカバー済みの部位は減点（同じ部位ばかりにならないように）
   - まだ主役として鍛えていない対象部位を埋める種目に加点（選んだ部位が満遍なく入るように）
   - コンパウンド種目、所有機材を使う種目に加点
   - 膝つき腕立てのような軽減バージョンは減点
   - 同じ動作パターンは最大2種目まで
3. 使える時間からウォームアップと有酸素を引いた残りを予算とし、セット数×(挙上時間+休憩)で埋まるまで選ぶ
4. 推奨重量は「体重 × 種目係数 × 経験係数 × 目標係数」を、所有しているダンベル重量に丸めて提示する

### 漸進性過負荷（`src/lib/progression.ts`）

前回その種目をやっていれば、上記4の計算より前回実績を優先する。
目標レップ数の上限を全セットで達成できていたら所有重量の1段階上へ、そうでなければ同じ重量で回数を伸ばす方針を出す。
手持ちで最大の重量に達している場合は、回数かセット数で負荷を上げるよう促す。

### アチーブメント（`src/lib/achievements.ts`）

- **連続日数** — 今日まだ記録していない時点では途切れた扱いにせず、昨日までで数える（1日の途中でストリークが0に見えないように）
- **週の進捗** — 実質の指標はこちら。週の目標を満たした日に休んでも罰されない設計にしてある（筋トレでは休養日が必要なため、毎日必須のストリークだけを指標にしない）
- **今日のミッション** — 毎日リセットされる4つ。減量・持久力の目標なら「有酸素10分」、それ以外なら「前回の総挙上量を超える」
- **バッジ** — 記録から毎回導出するだけなので状態を持たず整合性がずれない。獲得済みIDのみ localStorage に控え、増えた分を通知する

### 統計と目標調整（`src/lib/stats.ts`）

- 体重ペースは直近28日の最小二乗法で求める（日々の変動に振り回されないため）
- 必要ペースの7割を下回れば「遅い」、体重の約1%/週を超える減量は「速すぎ」と判定する
- 頻度が目標に届いていない場合は、目標を下げる提案をする（達成できない目標は続かないため）

### 自動評価（`src/lib/evaluation.ts`）

- 「やったかどうか」ではなく「前回からどう変わったか」を中心に見るので、続けるほど基準が上がる
- 毎回自己ベストを出せるものではないため、維持できていれば進歩の項目は半分の点が入る
- 所要時間が目安の3倍を超える場合（記録画面を開いたまま放置など）は計測不能として中立の点にする。実時間として扱うと不当に低評価になるため

### リマインダー（`src/lib/reminders.ts`）

ブラウザだけではサーバープッシュが使えないため、確実性の高い順に手段を用意している。
カレンダー書き出し (.ics) → Notification Triggers による予約 → 開いている間のタイマーと次回起動時の未実施表示。
どれが使えるかは端末で feature detection して設定画面に表示する。

### グラフ（`src/components/Chart.tsx`）

外部ライブラリなし。すべて単一系列なので凡例は置かず、見出しが系列名を兼ねる。
色はダーク `#e8632c` / ライト `#e2521c`（明度帯とコントラストを検証済み）。
ホバー／タップでツールチップが出て、各グラフに「数値で見る」の表を用意している。
viewBox の幅を実際の表示幅に合わせているので、狭い画面でも文字が潰れない。
